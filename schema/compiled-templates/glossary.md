# glossary.md — Schema Template (Structural Contract)

Purpose: Additive glossary of domain, technical, and process terms introduced across project artifacts.

## Format rules
- Each glossary entry MUST start with a level-2 heading: `## <Term>`
- Metadata fields SHOULD appear as a bullet list immediately after the heading.
- Entries are appended in the order they are encountered; the file is not re-sorted automatically.
- If information is unknown, fields may be omitted or set to `[unavailable]`.
- Do NOT redefine a term that already has an entry. If a term needs clarification, add a note to the existing entry instead.

## Glossary Entry Template

## <Term>

- **Category:** <domain | technical | process | [unavailable]>
- **Introduced in:** `raw/<path-to-source-file>`
- **Aliases:** <alias1, alias2 | omit if none>

<One or two sentence definition of the term as used in this project.>
